# CPU Baseline — 2026-07-04 (pre-optimization)

**Machine:** 8 logical cores.
**Metric:** process CPU normalized across all cores = `TotalProcessorTime` delta / wall-seconds / cores × 100. Multiply by 8 for approx single-core %.
**Build:** probe-instrumented, **pre** visibility-gate (Task 3 commit, before Task 4).
**Method:** launch `build_output/WinBGMuter.exe`, sample 20s, minimize, sample 20s. See PowerShell harness in session notes.

| Scenario | CPU % (norm, 8 cores) | ≈ single-core % | Notes |
|----------|-----------------------|-----------------|-------|
| Just launched (20s) | 2.168 | ~17% | MuterTimer active |
| After minimize (20s) | 1.748 | ~14% | MuterTimer **still runs** (no gate); `MainWindowHandle=0` → app sits in tray/hidden |

**Finding:** dominant idle cost is `MuterTimer` (2s) → `RefreshProcessList`
(`EnumWindows` + `VolumeMixer.GetPIDs` + per-PID `Process.GetProcessById` + ListBox rebuild),
which runs even while the window is hidden/minimized. An idle tray app should be ~0%.

**Expected after P3 visibility gate:** near-zero CPU when hidden/minimized.

## Post-P3 (visibility gate) — 2026-07-04

Build: gate applied (`RefreshGate.ShouldRefresh`), same harness.

| Scenario | CPU % (norm, 8 cores) | ≈ single-core % | Notes |
|----------|-----------------------|-----------------|-------|
| Window visible (20s) | 3.398 | ~27% | refresh runs — correct, user is viewing the list |
| **Minimized/hidden (20s)** | **0.049** | **~0.4%** | gate skips `RefreshProcessList` |

**Result:** idle (minimized) CPU **1.748% → 0.049% ≈ 97% reduction**. A tray app
spends ~all its time hidden, so this removes the dominant idle cost. Cost while
the window is open is unchanged (P4 event-driven session list will address that).
